# UniFlow

Telegram-бот для учебных задач на PHP 7.4+: вебхук, SQLite, планирование, напоминания и GigaChat. Python и Composer для запуска не нужны. Исходная Python-версия сохранена в `legacy/` для сверки и отката.

## Установка

Требуются 64-битный PHP 7.4+, расширения `curl`, `json`, `mbstring`, `pdo_sqlite`, SQLite 3.27+, HTTPS и PHP-FPM. Вебхук и обработчик должны работать на одном сервере с локальной SQLite-базой.

1. Скопируйте `.env.example` в `.env`. Заполните `BOT_TOKEN`, `WEBHOOK_URL` и `WEBHOOK_SECRET`. Секрет создайте командой `php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'`.
2. Проверьте `TIMEZONE`. По умолчанию оставлен прежний `Asia/Yekaterinburg`, UTC+5. Для Москвы укажите `Europe/Moscow`. Это единое время для всех пользователей; оно явно показано в боте.
3. Дайте пользователю PHP-FPM и обработчика доступ к `.env` и запись в `data/`. Например, запускайте оба от `www-data`. `.env` должен быть доступен только владельцу; новые файлы базы и резервных копий создаются с закрытыми правами при запуске CLI.
4. Остановите старый Python-процесс и его автоматический перезапуск. В один момент базу обслуживает только одна версия бота.
5. Запустите `php bin/console.php migrate` от пользователя обработчика. Для существующей базы команда сначала делает согласованную резервную копию SQLite через `VACUUM INTO`, затем обновляет схему в транзакции. Пользователи, задачи, отметки выполнения и абсолютные дедлайны сохраняются.
6. Настройте веб-сервер: корень сайта должен указывать **только на `public/`**, а не на весь проект. Пример Nginx: `deploy/nginx.conf`. Подставьте домен, сертификаты, путь проекта и сокет PHP-FPM.
7. Запустите `php bin/console.php worker`. Для постоянной работы установите `deploy/uniflow-worker.service`, подставив пути и пользователя. Включение: `systemctl enable --now uniflow-worker`.
8. Выполните `php bin/console.php webhook:set`, затем `php bin/console.php webhook:info`. Регистрация сохраняет ожидающие обновления Telegram.
9. Отправьте `/start` и пройдите сценарий `/add`. Проверьте `/today`, `/tasks`, изменение срока и напоминание на тестовой задаче.

Если нет systemd, используйте cron каждую минуту:

```cron
* * * * * /usr/bin/php7.4 /var/www/uniflow/bin/console.php worker --once >> /var/www/uniflow/data/worker.log 2>&1
```

`--once` обрабатывает доступную очередь до опустошения или мягкого лимита 50 секунд. Уже начатый HTTP-запрос завершается. Файловая блокировка не допускает наложения обработчиков. При cron ответ может задержаться до минуты; для обычной работы предпочтителен постоянный процесс. Настройте ротацию `worker.log`.

Вебхук только проверяет секрет и сохраняет обновление. Он не делает запросов в Telegram или GigaChat. **Без обработчика не будет ответов и напоминаний.**

## Что сохранено

- Ручное добавление: название, предмет, дедлайн, длительность, важность.
- Быстрый ввод и разбор до 10 задач с предпросмотром, уточнением полей, редактированием и подтверждением.
- Список задач с пагинацией, подробная карточка, завершение, редактирование и подтверждение удаления.
- План на сегодня, нагрузка на 7 дней, статистика и замена только демо-задач.
- Напоминания за 24 и 3 часа; отключение в настройках; согласие на внешний ИИ.
- Команды `/start`, `/add`, `/today`, `/tasks`, `/week`, `/stats`, `/settings`, `/ai`, `/explain`, `/demo`, `/help`, `/cancel`.

Старые reply-кнопки с обычными эмодзи распознаются. Старые кнопки подтверждения из Python требуют повторного открытия действия: временные Python-состояния в памяти не мигрируют. Новый пошаговый ввод сохраняется в SQLite на 24 часа. Бот работает в личном чате.

## Время

Выбор и подтверждение персонального пояса убраны. Ввод, отображение, план и напоминания используют один `TIMEZONE` из `.env`; часовой пояс операционной системы не влияет на расчёт. Без времени дедлайн равен 23:59 указанного дня. Даты хранятся в UTC в прежнем формате с микросекундами.

При миграции прежний `users.timezone` остаётся в базе как историческое значение, но PHP-бот его не использует. Старый дедлайн сохраняет тот же момент времени, поэтому при отличии прежнего персонального пояса от общего изменится отображаемое локальное время. Проверяйте это на копии базы до переключения. Полное удаление часового пояса сделало бы слова «сегодня» и «завтра» неоднозначными.

## GigaChat

Пока ключа нет, оставьте `GIGACHAT_ENABLED=false`: задачи, планы, напоминания и локальный разбор работают.

Для подключения:

```dotenv
GIGACHAT_ENABLED=true
GIGACHAT_AUTH_KEY=ключ_авторизации_Base64
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
GIGACHAT_BASE_URL=https://api.giga.chat/v1
```

`GIGACHAT_AUTH_KEY` - постоянный Authorization key из кабинета, без префикса `Basic`. Это не временный access token. Для другого типа договора задайте `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`. Модель должна быть доступна в вашем проекте. После изменения `.env` перезапустите обработчик.

Ключ обменивается на токен через OAuth с UUID4 в `RqUID`; токен кешируется в закрытой SQLite-базе и обновляется до истечения срока, а также один раз после HTTP 401. Используется актуальный адрес API. Источник: [авторизация GigaChat](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api).

TLS-проверка включена всегда. Если сервер требует дополнительный доверенный корневой сертификат, установите его по [инструкции провайдера](https://developers.sber.ru/docs/ru/gigachat/certificates) и укажите путь к доверенному CA bundle в `GIGACHAT_CA_BUNDLE`. Отключать проверку сертификатов не нужно.

Перед каждым ИИ-сценарием бот предлагает GigaChat или локальную обработку. Telegram ID, имя и username провайдеру не передаются. Текст задания может содержать введённые пользователем сведения. Согласие можно отозвать в настройках.

Ответы проходят проверку структуры и ограничений. Даты и длительности берутся из локального разбора только при точном уникальном совпадении названия; иначе бот просит их уточнить. Модель не меняет порядок и числовые расчёты плана, а выбирает только допустимые причины. При ошибке API работает локальный вариант. Частота запросов одного пользователя ограничена интервалом 10 секунд.

## Анимированные эмодзи

`src/Emojis.php` использует ID из приложенного файла. В сообщениях применяется HTML `tg-emoji`, в кнопках - `icon_custom_emoji_id`. Для календаря используется тематический значок времени, для списка заданий - книга, для удаления - крестик. Все служебные эмодзи проходят через единый обработчик, включая напоминания. Пользовательский HTML экранируется, длинные тире в отправляемом тексте заменяются обычным дефисом.

По [Telegram Bot API](https://core.telegram.org/bots/api#html-style), custom emoji доступны боту с дополнительным именем Fragment либо в прямых сообщениях бота при Telegram Premium у владельца. Сами ID не дают это право. Анимация также зависит от настроек клиента Telegram. При отсутствии права можно явно включить обычное отображение через `CUSTOM_EMOJI_ENABLED=false`. По умолчанию custom emoji включены. Реальные ID и доступ бота нужно проверить после добавления токена.

## Надёжность и обслуживание

- `update_id` уникален: повторная доставка не повторяет сохранение задачи. Состояние, изменение задачи, ответы в outbox и отметка обработки обновления фиксируются одной транзакцией.
- Регистрация использует `max_connections=1`, чтобы сохранить порядок входящих шагов.
- Только один PHP-обработчик владеет файловой блокировкой; сетевые операции не держат SQLite-транзакцию. Вебхук может записывать новые обновления параллельно.
- Перед отправкой напоминания повторно проверяются статус, ревизия, срок и настройки. После успешной отправки ставится отметка. При 429 вся отправка откладывается на `retry_after`; временные ошибки повторяются с увеличением задержки.
- Успешные сообщения и обновления очищаются от содержимого; идентификаторы хранятся 7 дней для дедупликации. Сессии удаляются через сутки.
- `php bin/console.php status` показывает очередь и ошибки доставки. После устранения причины можно повторить конкретную неудачную отправку: `php bin/console.php outbox:retry ID`. Неудачные сообщения сохраняются для этого в базе; доступ к ней должен быть ограничен.
- HTTP 403 отключает напоминания заблокировавшему бота пользователю до следующего входящего сообщения. HTTP 400 требует проверки настроек или содержимого по коду ошибки и журналу. Токены и ответы провайдера в журналы не записываются.
- После 5 ошибок обработки обновления бот сообщает пользователю о сбое, сохраняет номер обновления и продолжает очередь. Тексты уже обработанных обновлений очищаются.
- Нельзя гарантировать ровно одну отправку через сторонний API: при аварии после приёма сообщения Telegram, но до записи результата в SQLite, повтор возможен. Изменения задач при этом не дублируются.

## Проверки

```sh
php tests/php/run.php
```

Тесты используют временные SQLite-базы в памяти и подставной HTTP-клиент; реальные сообщения не отправляются. Проверяются миграция, UTC и переход летнего времени, формы, права владельца задачи, старые подтверждения, локальный разбор, GigaChat OAuth, напоминания и повторы доставки.

Для запуска именно на PHP 7.4 с Docker:

```sh
docker build -f deploy/Dockerfile.test -t uniflow-php74-test .
docker run --rm uniflow-php74-test
```

Точные результаты локальной проверки находятся в `VERIFICATION.md`.

## Откат

Остановите PHP-обработчик, удалите вебхук через Telegram `deleteWebhook` без сброса очереди, восстановите резервную копию базы и прежний `.env`, затем запускайте Python из `legacy/` по его исторической инструкции. Python-версия не поддерживает новую схему версии 2. Откат к резервной копии не включает задачи, созданные после миграции; сохраните новую базу отдельно перед откатом.
