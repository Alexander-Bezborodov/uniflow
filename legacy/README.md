# UniFlow 0.2

Обычный Telegram-бот: «Что сделать сегодня, чтобы ничего не просрочить?»
Python, aiogram 3, SQLite, FSM, inline/reply-кнопки и long polling. Команда запуска - `python main.py`.
ИИ необязателен: ручной ввод, быстрый локальный разбор, план, статистика и напоминания работают без него.

Изменения и проверенные дефекты: [BUGFIX_REPORT.md](BUGFIX_REPORT.md).
Фактические команды проверки: [VERIFICATION.md](VERIFICATION.md).
Матрица сценариев с отделением автоматических проверок от реальных API: [QA_CHECKLIST.md](QA_CHECKLIST.md).
Дерево файлов: [TREE.txt](TREE.txt).

## Установка и первый запуск

Поддерживается Python 3.12-3.14. Проверены Python 3.12.14 и 3.14.0 на macOS ARM64.
Прямые зависимости закреплены в `requirements.txt`; фактически проверенные версии сохранены.
Windows-инструкция подготовлена, но на Windows приложение не запускалось.

Распакуй архив и открой терминал **в папке `uniflow`, рядом с `main.py`**.

macOS:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python main.py --check
```

Можно использовать установленный `python3.14` вместо `python3.12`.

Windows, PowerShell (активация и изменение ExecutionPolicy не нужны):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe main.py --check
```

Создай собственного бота у [BotFather](https://t.me/BotFather) командой `/newbot`.
Вставь полученный токен **только в локальный `.env`**, в строку `BOT_TOKEN=`.
Не отправляй токен, API-ключ и личную базу в чат или репозиторий.
Если `.env` уже есть, сохрани его настройки, не заменяй шаблоном.

```dotenv
BOT_TOKEN=
TIMEZONE=Asia/Yekaterinburg
DATABASE_PATH=data/uniflow.db
LLM_ENABLED=false
LLM_API_KEY=
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=openai/gpt-oss-20b
```

После заполнения токена:

```sh
python main.py
```

В Windows: `.\.venv\Scripts\python.exe main.py`.
Открой личный чат с ботом → `/start` → выбери или подтверди часовой пояс → `/add`.
Остановить - Ctrl+C; повторный запуск той же командой. Сохранённые задачи и настройки остаются.
Незавершённые формы и предпросмотры находятся в памяти и после перезапуска вводятся заново.

Конфигурация читается из `.env` рядом с `main.py`; относительный `DATABASE_PATH` считается
от папки проекта. Чужой родительский `.env` и переменные окружения не подхватываются автоматически.

## Обновление старой версии и резервная копия

1. Останови старый процесс и сохрани прежнюю папку исходников.
2. Распакуй новую версию отдельно. Перенеси свой `.env`; укажи абсолютный путь к существующей
   базе в `DATABASE_PATH` либо перенеси **всю папку `data`** остановленного бота.
3. Установи зависимости новой версии. До её обычного запуска сделай копию:

```sh
python backup_db.py backup-before-update.db
python main.py --check
python main.py
```

`backup_db.py` читает путь из `.env`, использует SQLite Backup API, учитывает WAL, проверяет
целостность и не перезаписывает существующий файл. Сам скрипт не запускает миграцию.
`--check` использует только временную базу. Обычный запуск применяет миграцию `user_version: 0 → 1`
в транзакции; повторный запуск безопасен. ID, владельцы, дедлайны UTC, статусы, завершения,
старые флаги напоминаний, timezone и обычные задачи сохраняются.

Восстановление: останови новый процесс; сохрани его папку данных отдельно. В копии старого проекта
используй новый пустой каталог `data`, скопируй `backup-before-update.db` как `data/uniflow.db`
и укажи этот путь в `.env`. Не подкладывай к восстановленной БД WAL/SHM от другой копии.
Затем запусти старую версию. Восстановление возвращает состояние на момент резервного копирования.
Не удаляй личную базу ради применения схемы и не понижай `user_version` вручную.

## Команды и кнопки

| Команда | Действие |
| --- | --- |
| `/start` | Главное меню и проверка местного времени; настройки сохраняются |
| `/settings` | Москва, Екатеринбург, Новосибирск, Владивосток, UTC или другой IANA timezone; напоминания |
| `/add` | Название → необязательный предмет → дедлайн → длительность → важность |
| `/today` | План на сегодня, завершение, подробности, обновление, фильтр сроков сегодня, объяснение |
| `/week` | Прогноз на семь локальных календарных дней |
| `/tasks` | Активные задачи; «Подробнее» → редактирование, завершение, удаление |
| `/ai` | Выбор внешнего ИИ или локального разбора → текст → редактируемый предпросмотр |
| `/explain` | Выбор ИИ/локального шаблона для объяснения первых трёх задач актуального плана |
| `/stats` | Выполненные вовремя/поздно, активные и просроченные за всё время |
| `/demo` | Подтверждение замены только своих демо-задач |
| `/help` | Справка |
| `/cancel` | Отмена формы, предпросмотра, редактирования или ожидаемого AI-ответа |

Главное меню содержит «Сегодня», «Добавить задачу», «Все задачи», «Неделя», «Статистика»,
«Настройки», «Разобрать задание», «Объяснить план», «Помощь». Команды и меню прерывают
незавершённый сценарий. В формах есть «Пропустить» для предмета, «Отмена» и повтор ввода при ошибке.
«Оставить» при редактировании сохраняет прежнее значение.

Быстрый текст вне формы всегда разбирается **локально**. Для внешнего провайдера используй `/ai`.
Найденные задачи не записываются автоматически: «Добавить все» уточняет отсутствующие сроки
и длительности, снова показывает карточки и ждёт подтверждения. Пачка сохраняется одной транзакцией.
Предмет можно оставить неизвестным; важность по умолчанию - 2/3, она видна в предпросмотре.

Редактирование сохранённой активной задачи: «Подробнее» → «Редактировать» → одно поле →
новое значение → «Сохранить». Старое значение видно. До подтверждения БД не меняется;
«Отмена» ничего не сохраняет. Редактирование названия просроченной задачи не требует нового срока.
При конкурирующих изменениях устаревшее подтверждение отклоняется.

«Завершить задачу» завершает **всю** задачу. Повторное нажатие не увеличивает статистику.
Удаление требует отдельного подтверждения. Чужая, удалённая и завершённая задача не меняется
по старым кнопкам. Двойные подтверждения предпросмотра/демо расходуются один раз.

## Время, даты и оценка длительности

`TIMEZONE` - только начальный пояс. Выбор конкретного пользователя хранится в `users.timezone`;
повторные `/start`, callbacks и перезапуски его не сбрасывают. Пояс не определяется по языку
Telegram или компьютеру разработчика. В `/settings` показывается текущее местное время.
Старым пользователям предлагается подтвердить или изменить сохранённый пояс.

Один момент `2026-09-05T19:30:00Z` - 5 сентября 22:30 в Москве и 6 сентября 00:30
в Екатеринбурге. Поэтому один скриншот с 6 сентября не доказывает сбой часов.
Для тестов время подменяется через `AppContext.clock`; один расчёт плана получает один снимок времени.

- Без часов дедлайн - **23:59** выбранного дня; бот показывает результат до записи.
- Явное время сохраняется точно: `завтра в 18:17`, `10.09.2026 10:00`.
- Даты: `сегодня`, `завтра`, `послезавтра`, `через 3 дня`, `10.09`, `10.09.2026`,
  `10 сентября`, `2026-09-10`, `в пятницу`, `к следующему вторнику`.
- Без года выбирается ближайшая существующая дата не раньше сегодняшнего дня.
  `29.02` в 2026 году означает 29 февраля 2028 года. Явный неверный год не исправляется.
- «В пятницу» - ближайшая пятница, включая сегодня; «в следующую пятницу» - строго после сегодня.
  Это не правило «обязательно на следующей календарной неделе».
- Неоднозначные форматы `10/09`, двухзначный год и невозможные даты требуют исправления.
  Формат с точками - день.месяц; явный прошлый срок не переносится незаметно.
- Несуществующий час при весеннем DST отклоняется. Повторяющийся осенний час трактуется как
  первое вхождение (`fold=0`, более ранний абсолютный момент); результат можно проверить в карточке.
- Новые задачи и изменения срока проверяются при вводе и при окончательном сохранении.
  Если срок истёк во время формы/предпросмотра, бот просит новый.
- Дедлайны хранятся как aware UTC. Смена timezone сохраняет абсолютный момент и меняет
  отображение; заголовки, «сегодня/завтра», неделя, демо, статистика, напоминания и LLM-контекст
  используют пояс владельца.

Оценка: `30 минут`, `1 час`, `1.5 часа`, `1,5 часа`, `1 час 30 минут`, `полчаса`,
`полтора часа`; в ручном поле число без единиц означает минуты. Допустимо 1-10080 минут,
дробный результат округляется вверх до минуты. Ноль, отрицательные и слишком большие значения
требуют исправления. Название - 1-200 символов, предмет - до 100, важность - 1, 2 или 3.

## Приоритеты и планирование

| Остаток до дедлайна | Базовый приоритет |
| --- | --- |
| Срок наступил/прошёл | Критический, явное «ПРОСРОЧЕНО» |
| До 24 часов включительно | Очень высокий |
| До 72 часов включительно | Высокий |
| До 168 часов включительно | Средний |
| Более 168 часов | Низкий |

Важность 3 **или** оценка от 180 минут повышает уровень на один, максимум до очень высокого.
Бонусы вместе не складываются. Сортировка: приоритет убывает → срок возрастает → важность
убывает → оценка убывает → ID возрастает. Приоритет обозначен словами, а не только цветом.

Рекомендация для задачи с оценкой `M`:

```text
D = max(1, deadline_local.date - today_local.date)
Если до срока <= 24 ч либо D == 1: M минут сегодня.
Иначе: min(M, max(5, ceil(M / D))) минут сегодня.
```

Будущие сроки входят в сегодняшний план: к ним нужно готовиться заранее. В карточке отдельно
подписаны «Поработать сегодня», «Дедлайн» и «Оценка всего». Верхний лимит 180 минут снят:
1000 минут за 3 дня → 334 минуты сегодня. Перегрузка выше 6 часов за день видна явно.
Фильтр «Дедлайны сегодня» показывает только задачи с сегодняшней локальной датой сдачи;
просрочка видна в «Весь план». Его сумма относится к выбранным задачам.

Порядок, минуты карточек и общая сумма `/today` берутся из одного результата `PlanningService`.
`/week` виртуально вычитает рекомендации из остатка оценки, не повторяет полный объём ежедневно
и имеет тот же первый день, что `/today`. Для срока завтра работа предлагается целиком сегодня;
для просроченных задач - тоже сегодня. У длинных задач часть работы может лежать за пределами
семидневного окна, но не за их будущим дедлайном.

Фактически отработанные минуты не учитываются - журнала прогресса в этой версии нет.
Недельный прогноз **предполагает выполнение рекомендаций**; при открытии на следующий день
активная задача снова рассчитывается от своей полной оценки. Это явно подписано в интерфейсе.

Сообщение Telegram - снимок. «Обновить план» пересчитывает дату, порядок и суммы, стараясь
редактировать текущую страницу. Если сообщение уже нельзя редактировать, отправляется новое.
Фоновое обновление всех старых сообщений не выполняется. Пагинация учитывает длину текста
после HTML и UTF-16; пользовательский текст экранируется. Ограничения API сверены с
[Telegram Bot API](https://core.telegram.org/bots/api#sendmessage).

## Подключение Groq

По документации на 05.09.2026 `openai/gpt-oss-20b` доступна в каталоге Groq и поддерживает
строгий `json_schema`. Используются `https://api.groq.com/openai/v1/chat/completions`,
`response_format: json_schema`, `strict: true` и `max_completion_tokens: 3000`.
Для другой модели/совместимого провайдера - `json_object` с обязательной проверкой Pydantic;
поддержку параметров нужно проверить у выбранного провайдера.
Источники: [модели](https://console.groq.com/docs/models),
[структурированные ответы](https://console.groq.com/docs/structured-outputs),
[API](https://console.groq.com/docs/api-reference),
[совместимость](https://console.groq.com/docs/openai).

1. Войди в [Groq Console](https://console.groq.com) из своего региона и аккаунта.
2. Убедись, что остаёшься на Free tier и нужная модель доступна. Создай API-ключ.
3. В своём `.env` установи `LLM_ENABLED=true`, заполни `LLM_API_KEY`; оставь базовый URL
   и `LLM_MODEL=openai/gpt-oss-20b` из шаблона.
4. Явно запусти диагностику:

```sh
python main.py --check-llm
```

Она отправляет **один** короткий синтетический пример напрямую провайдеру, проверяет JSON,
оценку 30 минут и завтрашний дедлайн 23:59. База и Telegram не используются. Fallback отсутствует:
ошибка провайдера/схемы/фактов даёт ненулевой код; без настроенного ключа код 2.
Успех этой команды доказывает только данный вызов разбора; объяснение и реальные сообщения
надо отдельно пройти в собственном тестовом боте.

Free tier существует, но не означает безлимит или бесплатный хостинг процесса бота.
Публичная таблица для модели на дату сверки: 30 запросов/мин, 1000/день, 8000 токенов/мин,
200000/день; действительные квоты смотри в своём аккаунте. Бот не меняет тариф или модель
и не подключает платный план автоматически.
[Лимиты](https://console.groq.com/docs/rate-limits),
[Free tier FAQ](https://community.groq.com/t/is-there-a-free-tier-and-what-are-its-limits/790).

Доступность именно твоего региона, аккаунта и ключа здесь **не подтверждена**.
При ограничении доступа проверь Console/поддержку Groq; локальный режим остаётся доступен.
Реальные запросы Groq при разработке не выполнялись: ключ не предоставлялся и не запрашивался в чате.

## Как устроены две AI-функции

`/ai` и `/explain` сначала объясняют передачу внешнему провайдеру и предлагают кнопки
«Использовать ИИ» / «Локальный вариант». Кнопка внешнего ИИ появляется только при полных настройках.
Каждый запуск требует явного выбора. Факт согласия хранится в настройках; его можно отключить.
Простой быстрый ввод не передаётся провайдеру.

Разбор возвращает названия, предмет, дату, минуты и важность. Неизвестные дата/предмет/минуты -
`null`, важность по умолчанию 2. Внешний JSON строго проверяется: обязательные поля, типы,
диапазоны, aware-даты, число задач и отсутствие лишних полей. Учебный текст обозначен недоверенными
данными; код, инструменты и инструкции из него не исполняются. Сохранение - только после кнопки.

Для понятной локальному парсеру грамматики даты и длительности дополнительно привязаны к исходному
тексту через однозначное сопоставление названий. При неоднозначных названиях или разном числе задач даты и минуты сбрасываются
в `null` для уточнения. Это намеренно консервативно: сложный оборот может потребовать ручного срока.
Общий срок наследуется только из явного вводного контекста перед перечнем. Отдельная задача без срока
или с ошибочной датой не получает срок первой задачи. Произвольное понимание языка не гарантируется.

Для объяснения передаются максимум первые 10 задач рассчитанного плана: названия, даты,
оценки, приоритеты, рекомендации и допустимые причины. Вместо реальных ID используются позиции.
Модель выбирает причины для первых трёх задач, не меняет порядок и копирует проверяемые факты.
Неизвестная ссылка, другая дата, другое число минут или недопустимая причина отклоняется.
Пользовательское объяснение строится русскими шаблонами из проверенных данных - свободный текст
модели не выводится. Сроки и суммы не меняются в БД. При изменении плана во время ответа используется
актуальный локальный расчёт. Пустой план обрабатывается без API.

Защита от выдумок не сводится к system prompt: есть схема, привязка к тексту, проверка фактов
и подтверждение пользователя. Качество названия/предмета всё равно нужно проверить в предпросмотре.

Ограничения клиента: ввод до 6000 символов и 10 задач; ответ до 64 КиБ; генерация до 3000 токенов;
общий timeout 20 с, HTTP 18 с, подключение 5 с; максимум два параллельных запроса,
два запроса за скользящие 60 с на процесс и один за 20 с на пользователя. Это не замена квотам
провайдера по токенам/суткам. При 429 соблюдается общий `Retry-After`; автоматических повторов нет.
401, 403, 404, 400, 5xx, таймауты, обрывы, отказ/оборванный ответ и ошибки схемы дают fallback.
Логи различают безопасные категории (`http_401`, `http_429`, `timeout`, `connection`, `schema`,
`inconsistent_explanation`), не печатают ключ, текст задания или тело ошибки провайдера.

Telegram ID используется только локально для квоты и БД: профиль, username, диалог,
чужие задачи и `.env` не включаются в API payload. Ответы не кешируются.
Повторные подтверждения не вызывают API ещё раз. Во время запроса показывается обработка;
`/cancel`/меню отменяют сценарий, поздний ответ не открывает его заново. Другие пользователи
не ждут завершения чужого LLM-запроса.

## Напоминания, статистика и демо

Один asyncio background task проверяет напоминания сразу после запуска и примерно раз в 60 с.
Окна: `3 ч < остаток <= 24 ч` → «24 ч»; `0 < остаток <= 3 ч` → «3 ч».
При первом запуске за два часа до срока отправится только «3 ч».
Просроченные, завершённые и удалённые задачи не уведомляются.

Флаг записывается **после** успешной отправки. Обычно отправленное уведомление не повторяется,
включая перезапуск. Сеть/5xx оставляют его доступным для следующего прохода; TelegramRetryAfter
откладывает проходы, не блокируя event loop. Блокировка пользователем хранится отдельно от ручного
выключения напоминаний; новый контакт снимает техническую блокировку, не меняя ручной выбор.

Изменение дедлайна увеличивает ревизию задачи и сбрасывает её флаги; устаревший снимок не отправляется.
В одном процессе отправка, изменение, завершение и удаление одного пользователя сериализованы.
Уже начатая отправка может закончиться **до** фиксации завершения; после фиксации новые отправки исключены.

У SQLite и Telegram нет общей транзакции. При аварии после доставки, но до записи флага возможен повтор.
При аварии до доставки флаг остаётся несохранённым, и бот попробует снова, пока срок ещё впереди.
Гарантии exactly-once и доставки при выключенном боте нет. Уже прошедшие окна после долгого простоя
не воспроизводятся. Старые флаги из базы сохраняются: невозможно узнать, что случилось до миграции.

Запускай один процесс с токеном. Локальная OS-блокировка препятствует дублирующему запуску на
том же компьютере; запуск на двух разных машинах она не предотвращает. У каждого бота должна быть
своя база. Для круглосуточных напоминаний нужен постоянно работающий компьютер/хостинг.

Статистика за всё время: выполнено, вовремя, поздно, активно, из активных просрочено.
Процент = вовремя / все завершённые × 100, округлён до целого. Пустой знаменатель даёт пояснение.
Демо включено в статистику и отмечено в карточках.

`/demo` после подтверждения заменяет только демо текущего пользователя, включая выполненные:
Java - завтра/120 мин; математика - через 3 дня/180 мин; английский - через 5 дней/60 мин;
история - через 7 дней/45 мин. Все сроки в 23:59 от локальной даты пользователя.
Обычные задания и чужие данные сохраняются; двойной клик не создаёт дубликаты.

## Демонстрация на 2-3 минуты

Подготовь собственный тестовый бот и заранее проверь `--check`; для AI-показа отдельно `--check-llm`.

1. `/start`: выбери пояс, покажи местные часы. `/demo` → подтверждение.
2. `/today`: покажи отдельные строки работы сегодня и будущего дедлайна, затем `/week`.
3. Отправь `Лаба по Java до пятницы 2 часа`, проверь карточку и нажми «Добавить все».
4. `/ai` → выбери доступный способ → вставь сообщение ниже. Покажи неизвестные минуты,
   заполни их через «Добавить все», отредактируй название в предпросмотре и подтверди.
5. `/today` → «Объяснить план» → способ обработки. Назови фактический источник ответа.
6. «Подробнее» → измени одно поле → «Сохранить». Заверши задачу и покажи `/stats`.

Готовые тексты:

```text
Лаба по Java до пятницы 2 часа
```

```text
Сделать дз по матану завтра, примерно час
```

```text
Коллеги, к следующему вторнику необходимо выполнить лабораторную работу №3, прочитать главы 4-5 и подготовиться к контрольной работе
```

У последнего текста три задачи с общим сроком, без выдуманных длительностей.
Для демонстрации уточнения можно ввести 60, 30 и 90 минут.

```text
Сдать эссе завтра; подготовить презентацию
```

У второй задачи срок неизвестен; обе оценки неизвестны.

Отдельно, вне короткой защиты, проверь настоящее напоминание: у **собственной** задачи поставь срок
через 10-15 минут, включи напоминания и оставь процесс работающим около минуты. Дождись сообщения,
заверши задачу, проверь отсутствие повторов и сохранение данных после перезапуска.
Эта ручная сетевая проверка здесь не проводилась; не используй рассылку реальным пользователям.

## Проверки и диагностика проблем

В активированном окружении из папки проекта:

```sh
python -m pytest
ruff check .
ruff format --check .
python -m pip check
python -c "import main"
python main.py --check
```

`--check` импортирует все модули, читает настройки, создаёт временную БД,
собирает Dispatcher/handlers/FSM, проверяет пустой проход напоминаний. Реальную базу и API не трогает.
HTTP-тесты запускают поддельный провайдер только на `127.0.0.1`; среда должна разрешать локальные сокеты.
Остальные тесты используют временные SQLite и mock Telegram. Это не доказательство работы реальных API.

| Симптом | Действие |
| --- | --- |
| День сдвинут | Открой `/settings`, сравни местное время, выбери пояс, нажми «Обновить план» |
| Старое сообщение не изменилось само | Обнови его кнопкой; сообщения являются снимками |
| Неизвестная/прошедшая дата | Введи `ДД.ММ.ГГГГ в ЧЧ:ММ`; проверь пояс и DST |
| `BOT_TOKEN` / Unauthorized | Проверь токен своего бота в `.env`; не публикуй его |
| Бот уже запущен / TelegramConflictError | Останови второй polling-процесс, в том числе на другом компьютере |
| Локальный разбор вместо ИИ | Проверь `LLM_ENABLED`, три LLM-поля и запусти `--check-llm` |
| `http_400` / `schema` | Проверь совместимость модели, JSON Schema и параметров; смотри категории логов |
| `http_401` | Неверный/отозванный ключ; создай новый в Console и замени локально |
| `http_403` | Проверь доступ региона/аккаунта/модели в Console; оставайся в локальном режиме |
| `http_404` | Проверь базовый URL без `/chat/completions` и текущий ID модели |
| `http_429` / `provider_cooldown` | Дождись сброса квоты/Retry-After; используй локальный разбор |
| `local_rate_limit` | Подожди 20-60 секунд; лимит общий для двух AI-функций |
| `timeout` / `connection` / 5xx | Проверь сеть; запрос даст локальный результат, следующий вызов доступен по квоте |
| Нет напоминания | Бот должен работать, пользователь - начать личный чат; проверь настройки, срок и флаги |
| Ошибка миграции / database locked | Останови лишние процессы, сохрани резервную копию, проверь права; не удаляй базу |
| Старые кнопки не действуют | Открой актуальную команду; формы не сохраняются между перезапусками |

Дополнительные журналы личных данных, `.env`, SQLite, окружения и кэши в передаваемый архив не включены.
